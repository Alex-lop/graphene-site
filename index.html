The problem

Running one agent is a conversation. Running five is a scheduling problem.

And the scheduler is you. The failures are boringly predictable once you have watched them a few times. Two agents settle the same open question in opposite directions, both confidently. One quietly overwrites the other’s file, and nothing notices, because nothing was watching that file. Work piles up in places nobody owns until the next merge is a negotiation. A step fails, the retry gets the same instructions as the first attempt, and fails the same way — a little slower and a little more expensively.

The usual answer is more coordination prompt: sharper instructions, a shared scratchpad, a stricter persona. That is asking the probabilistic part of the system to be the reliable part.

Graphene answers with a contract instead. One approved DAG per mission. A read scope and a write scope per worker, enforced rather than requested. Checks as the only definition of done. And a lineage that outlives the run, so “why is this file like this?” has an answer that is derived rather than remembered.

An agent swarm is a compiler that is probabilistic at every step. The plan is the step that does not have to be.

Boundaries

What Graphene is not.

Not a context layer. Graft and Aider’s repo map give an agent a better picture of your codebase so it chooses well; Graphene assumes the choice is already made and makes it binding.

Not a planning notebook. CoderMind, Beads and Task Master hold the plan where agents can read it; Graphene’s plan is executed by a scheduler that refuses work outside it, fences retries, and will not call anything done without its check.

Not a harness. Your agents keep whatever harness they already run in. Graphene sits above them, holding the scopes, the checks and the evidence.
